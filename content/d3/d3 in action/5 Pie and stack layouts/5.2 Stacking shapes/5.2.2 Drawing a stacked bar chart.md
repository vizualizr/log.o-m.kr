## Steps

기본 순서는 동일하다.

1. [[d3/d3 in action/5 Pie and stack layouts/5.2 Stacking shapes/5.2.2 diagram.canvas#7213f05aab9769ea|stack data generator]]를 생성한다.
2. Layout Generator에 데이터를 전달한다. 단 데이터의 행, 열은 Layout의 구조에 맞춰 바꿔야 한다.
3. 원하는 DOM을 선택해 새로운 [[d3/modules/d3-selection/d3.Selection|d3.Selection]]을 생성한 뒤 이 `Selection`에 Layout Data(책에서는 `annotatedData`라는 이름으로 부른다)를 전달해 SVG 요소를 추가한다.

이 때 stacked bar를 위한 레이아웃은 다음 구조를 따른다.

![[backoffice/attachments/Pasted image 20260817230607.png]]
“Figure 5.13 Annotated dataset returned by the stack layout generator” ([Meeks, 2024, p. 170](zotero://select/library/items/VHTGXJRT)) ([pdf](zotero://open-pdf/library/items/FGBNWKIT?page=196\&annotation=R98H6BVS))

Streamgraph의 annotated data의 구조가 좀 어렵다. 배열의 구조를 설명하면 아래와 같다.

- 2차원으로 중첩된 다차원 배열이다.
  - 1차원은 계열의 집합, 즉 키(key)값으로 지정한 계열의 숫자와 동일한 개수의 원소를 가진다.
    - 여기서는 vinyl, eight track, cassette, cd, download, streaming, other와 대응하므로 가장 외곽에 있는 1차원 배열의 길이는 7이다.
  - 2차원은 해당 계열의 연도별 데이터 포인트이다. 47년 동안의 기록이므로 길이가 47인 배열이다.
    - 각 배열은 아래값을 가진다.
      - 해당 계열이 해당 연도에서 차지하는 막대의 경계값.
      - \[하단 경계 수치값, 상단 경계 수치값]
      - `data`라는 이름의 객체에 해당 연도의 원본 데이터를 모두 저장한다.
- 다이어그램에서 [[d3/d3 in action/5 Pie and stack layouts/5.2 Stacking shapes/5.2.2 diagram.canvas#b4e39b365dfb38ae|Stack data]]를 확인하라.

## Troubleshooting

- 데이터를 각 연도별로 저장하지 않고 계열 아래 연도별로 데이터를 저장하는 이유는?
  \- d3가 계열을 먼저 그리는 방식을 취하기 때문이다.
  \- 실제로는 각 계열을 하나씩 그리는 방식을 취한다.
  \- 스트림그래프는 d3.area()를 사용해 하나의 연속된 면을 그린다. 따라서 특정 계열을 먼저 그려야 한다. 이를 위해 annotated data의 1차 배열은 연도가 아닌 계열이어야 한다.
